# Процесс заполнения и проверки ежедневного отчёта

## 1. Участники процесса

**Сотрудник** — заполняет ежедневный отчёт, указывает выполненные работы и фактически затраченное время, передаёт отчёт и при необходимости исправляет выявленные ошибки и замечания.

**Проверяющий** — проверяет полноту и корректность сведений в отчёте, принимает его либо возвращает сотруднику с замечаниями. Кто именно выполняет эту роль, необходимо уточнить у куратора.

**Система 1С:Документооборот** — обеспечивает загрузку данных из Excel и автоматическую проверку корректности заполнения. Исполнитель загрузки и конкретные правила проверки уточняются.

## 2. Сценарий работы с ежедневным отчётом

| № | Действие                                                                                            | Ответственный                               | Результат                                                |
| - | --------------------------------------------------------------------------------------------------- | ------------------------------------------- | -------------------------------------------------------- |
| 1 | Заполнение ежедневного отчёта по шаблону Excel: дата, проект, выполненная работа, фактические часы  | Сотрудник                                   | Подготовлен отчёт за рабочий день                        |
| 2 | Передача заполненного отчёта для загрузки в 1С:Документооборот                                      | Сотрудник                                   | Отчёт передан для обработки                              |
| 3 | Загрузка данных из Excel и автоматическая проверка обязательных полей, форматов и дубликатов        | Система 1С; исполнитель загрузки уточняется | Получены результаты проверки данных                      |
| 4 | Если обнаружены ошибки заполнения — их исправление и повторная передача отчёта                      | Сотрудник                                   | Исправленный отчёт повторно проходит загрузку и проверку |
| 5 | Если автоматическая проверка пройдена — проверка сведений о выполненных работах и затраченных часах | Проверяющий                                 | Принято решение по отчёту                                |
| 6 | Если замечаний нет — принятие отчёта                                                                | Проверяющий                                 | Проверка завершена, отчёт принят                         |
| 7 | Если обнаружены замечания — возврат отчёта сотруднику с указанием причин                            | Проверяющий                                 | Отчёт направлен на исправление                           |
| 8 | Исправление замечаний и повторная сдача отчёта                                                      | Сотрудник                                   | Отчёт повторно направлен на обработку и проверку         |

**Порядок переходов:** если автоматическая проверка выявляет ошибки, сотрудник исправляет их и повторяет сдачу отчёта. При успешной автоматической проверке отчёт поступает проверяющему. Проверяющий принимает отчёт либо возвращает его с замечаниями. После исправления замечаний процесс проверки повторяется.

Описанный порядок является предлагаемым сценарием и требует согласования с куратором.

## 3. Результат процесса

Результатом процесса является ежедневный отчёт с проверенными сведениями о фактических трудозатратах сотрудника по проектам.

Полученные данные предназначены для формирования аналитического дашборда в 1С:Документооборот, позволяющего сравнивать плановые и фактические часы, анализировать загрузку сотрудников и выявлять отклонения по проектам.

При этом необходимо уточнить, должны ли в аналитике учитываться все успешно загруженные отчёты или только принятые проверяющим.

## 4. Вопросы для уточнения у куратора

1. **Порядок сдачи и проверки:** сотрудник самостоятельно загружает Excel в 1С или передаёт файл ответственному лицу? Кто назначается проверяющим?
2. **Сроки:** до какого времени сотрудник должен сдавать ежедневный отчёт и в какой срок проверяющий должен его обработать?
3. **Статусы:** какие состояния отчёта необходимо предусмотреть? Например, «Черновик», «На проверке», «Принят», «Возвращён на исправление». Предложенные статусы требуют подтверждения.
4. **Повторная проверка:** требуется ли повторное согласование исправленного отчёта и сохранение истории изменений и замечаний?
5. **Использование данных:** должны ли в аналитическом дашборде учитываться только принятые отчёты или все отчёты, успешно прошедшие автоматическую проверку?
